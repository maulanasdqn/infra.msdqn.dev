# Darwin (macOS) modules

nix-darwin configuration, split by concern.

| Directory | Purpose |
|---|---|
| `defaults/` | `system.defaults` — global UI/UX and performance daemons |
| `system/` | System-level settings, single-owner tweaks |
| `homebrew/` | Homebrew integration |
| `services/` | LaunchDaemons (PostgreSQL) |
| `aerospace/` | AeroSpace tiling WM |
| `sketchybar/` | Status bar |

## `enableAggressiveTweaks`

The single most important flag in this tree. It gates machine-wide,
single-owner behaviour:

- firmware NVRAM boot-args
- HID keyboard remap
- global power management (pmset)
- performance LaunchDaemons
- system-wide PostgreSQL
- Homebrew `cleanup = "zap"`

`true` on the MacBook (sole owner). `false` on the shared Mac mini, where these
would affect another account.

Modules like `defaults/performance.nix` and `services/postgres.nix` are imported
**unconditionally**, with the gate applied *inside* the module — a module
argument cannot drive an `imports` list.

## SSH authorized keys

`default.nix` populates `/etc/ssh/nix_authorized_keys.d/${username}`, which
nix-darwin's sshd reads as root via `AuthorizedKeysCommand`.

This is deliberate. A home-managed `~/.ssh/authorized_keys` is a `/nix/store`
symlink, which sshd's `StrictModes` rejects with *"bad ownership or modes for
directory /nix/store"*. Inbound keys therefore go through
`users.users.<name>.openssh.authorizedKeys.keys`, never through home-manager.
See `../home/ssh/README.md`.

## Manual generation disabled

`system/default.nix` skips the nix-darwin manual and man pages. Their
`options.json` is generated by nixpkgs' `nixosOptionsDoc`, which on current
nixpkgs-unstable references the nixpkgs source path without string context and
emits a build-time warning. Nothing here uses `man darwin-configuration` or
`darwin-help`.
