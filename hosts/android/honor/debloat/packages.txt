#
# DO NOT add com.hihonor.android.launcher here — it must stay ENABLED (2026-07-29).
# Lawnchair IS the home screen; the stock launcher is kept enabled purely as the
# recents host. SystemUI's config_recentsComponentName is fixed to the stock launcher
# at build time, so it binds there regardless of which app is HOME — but only if the
# package is enabled. Disabling it kills the app switcher entirely (and under gesture
# nav kills swipe-up/back/home too, bricking navigation).
#
# The working launcher setup, for a fresh device — no disable step:
#   adb shell cmd package set-home-activity \
#     app.lawnchair.play/app.lawnchair.LawnchairLauncher
#   adb shell am crash com.android.systemui     # forces rebind; re-locks the screen
# Verify (must show the STOCK launcher bound, with client c:com.android.systemui):
#   adb shell dumpsys activity services TouchInteractionService
#   # good: com.hihonor.android.launcher/.quickstep... app=ProcessRecord{...} c:com.android.systemui
#   # bad:  app.lawnchair.play/...  app=null  c:app.lawnchair.play  (self-bound, never attached)
# Cost of leaving it enabled is only ~134MB (background service host) vs ~287MB when it
# was also drawing the home screen.
#
# Why Lawnchair can never host recents itself: SystemUI binds only to a
# TouchInteractionService declared with android.permission.STATUS_BAR_SERVICE, a
# signature|privileged permission. `pm grant app.lawnchair.play
# android.permission.STATUS_BAR_SERVICE` fails outright with "not a changeable
# permission type". It would need /system/priv-app => root => unlocked bootloader.
#
# DO NOT add com.hihonor.hnoffice here — it is the Yozo/WPS render backend for
# PDF/Office preview in Honor Files. Disabling it makes every PDF open fail with
# "Unsupported File Type". It must stay ENABLED.
